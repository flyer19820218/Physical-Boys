## 3. 接力規則

- **領取**：開工前先在 §7 日誌最上面加一行「領取：階段、帳號代號、日期」，並 commit＋push。已經有人「進行中」就不要同時做同一階段；不同階段如果互不依賴可以並行，但要在日誌寫清楚。
- **只動自己的檔案**：`index_museum.html`、`assets/museum/`、`tools/museum/`、`galileo-planet/`。**不要動 `index.html`、任何課程頁、`PROGRESS.md` 以外的共用檔**（四個帳號同時在改它們）。最終切換 `index.html` 要等老師明確說。
- **commit 小而勤**：一個功能一個 commit，commit 訊息寫清楚做了什麼，換人時才看得懂。每次推送前先 `git fetch origin main` 再 rebase。
- **收工交棒**：在日誌最上面加一筆，固定寫這幾項：做到哪／沒做完的／已知問題／下一步建議／檢查結果／最後 commit SHA。再把 §1 看板更新。
- **品質第一，不急**。`AGENTS.md` 13.5：老師的原則是省 token，但品質與省 token 衝突時品質優先。
- **分工建議**：3D 場景與互動的複雜模組（星球、攝影機飛行、arcball、各展品）用 Opus，一次只開一個 Opus；資料腳本、CSS、文案、檢查腳本、截圖用 Sonnet。給代理的簡報要精簡，只放這個任務需要的檔案與規則。
- **不確定就問老師，不要猜**：尤其是 `PLAN.md` §10 待確認事項。

## 5. 環境與工具備忘

- 本機伺服器：`tools/qa/serve.sh`（`http://127.0.0.1:8765/`）。
- Playwright：`tools/qa/lib.cjs` 的 `launch()` 會找瀏覽器；Node 在 `/opt/node22/bin/node`。
- **雲端沙箱連不到 Google Fonts**，頁面載入會卡住：測試時要在 context 擋掉 `fonts.googleapis.com`／`fonts.gstatic.com`（`ctx.route(/fonts\.(googleapis|gstatic)\.com/, r => r.abort())`），並用 `waitUntil: 'domcontentloaded'`。字體沒載到時，任何「字寬塞不塞得下」的結論都無效（`AGENTS.md` 10.5）。
- **雲端是軟體 WebGL**：若 headless Chromium 建不起 WebGL，試 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`。軟體算圖只能驗「畫得出來、沒報錯」，**幀率數字沒有意義**。
- 取得 Three.js：在暫存資料夾 `npm i three`，複製 `build/three.module.min.js` 與授權檔進 `assets/museum/vendor/`（npm 在沙箱允許清單內）。
- 課程頁封面有兩種來源：`assets/index_covers/...`（首頁卡片）與 `assets/covers/...`；`lessons.json` 的 `cover` 一律用首頁卡片實際使用的那一張。
- 檢查腳本放 `tools/museum/`；截圖與暫存放 scratchpad，**不要提交**。

## 2026-10-27 蟲洞改成星際效應式（版本 20261027h）
老師看了巨人黑洞版說「隧道的感覺怪怪的，那麼亮嗎？」，又更正「蟲洞不需要螺旋進洞，螺旋墜入是黑洞的模型」→ `launch.js` 的蟲洞段整段重寫成《星際效應》裡的**蟲洞**（介面不變：`makeWarp(warpMs)` 回傳 `draw(ctx,W,H,tau,w,p,dt)`、`WARP_MS = 6000`、`drawFlash`；museum_v1.js 流程、旁白、sfx.js 都沒動）。
- **給學生的科普**：電影裡的蟲洞是一顆「水晶球」，不是隧道。這裡畫的是 Ellis 蟲洞 ds² = −dt² + dl² + (b² + l²)dΩ²（喉嚨半徑 b＝1；l>0 我們的宇宙、l<0 另一個宇宙）。它沒有質量、沒有事件視界、本身不發光。球裡看到的是**另一邊宇宙的天空**（光穿過喉嚨過來）；球外是我們的星空，被彎曲的空間偏折——越靠近球邊緣扭曲越大，銀河帶被拉彎、星星被拉成一圈圈弧線。穿越時沒有亮光隧道，只是另一邊的天空越來越大、佔滿視野。放射光絲的「時空隧道」是科幻傳統，不是物理。**蟲洞不螺旋：螺旋墜入、時間膨脹變紅、潮汐拉長都是黑洞的模型。**參考 James, von Tunzelmann, Franklin & Thorne, Am. J. Phys. 83, 486〈Visualizing Interstellar's Wormhole〉。
- **真的光線追蹤**：撞擊參數 B＝r_c sin α（α＝像素和「朝蟲洞中心」的夾角）；dφ/dl = B/(r√(r²−B²))。B<1 穿過喉嚨看到另一邊，B>1 在 r=B 折回看到這邊。總偏折 φ = K(B) − F(|l_c|,B)（朝喉嚨）或 F(|l_c|,B)（背向喉嚨）：K(B) 用代換 l = √(1−B²) sinh w／√(B²−1) cosh w 變成平滑積分（轉折點的 1/√ 奇異消失），以 ln|B−1| 為座標做成 1024 格的表；F 每格用 16 點高斯積分現算。和暴力積分比對到小數第 4～5 位。
- **每格怎麼畫**：畫面對蟲洞中心旋轉對稱 → 每格只算一條「離中心距離（¼ 像素一格）→ φ」的表，再逐像素查兩張天空貼圖（低解析度畫布：寬 ≤ 360、像素 ≤ 11 萬，最後放大）。天空貼圖是以視軸為極軸的經緯圖（極點附近每列格子較少），8 層 mip：被透鏡壓縮的地方取糊一點的那層（另外保留一點最亮值，壓縮處還看得到星光）；壓到極限（球邊緣、光線繞無數圈）直接用整片天空的平均色 → 邊緣不閃爍。球邊緣再用畫布解析度畫細亮的暖色邊緣光＋紅藍微微錯開（色散）＋很淡的光暈。

- **架構（`launch.js` 的「高清 GL 路徑」段落）**：`startLaunch` 一開始呼叫 `hdInit(root, cv)`，在原本半解析度的煙霧畫布上面插入三個元素：全解析度 WebGL 畫布（WebGL2 優先，沒有就 WebGL1）、只有太空梭那麼大的 2D 畫布（全解析度，用 CSS 位移跟著走）、出洞閃光 div。GL 在歡迎詞與煙霧時分段建好（每段 ≤ 8 ms；有 `KHR_parallel_shader_compile` 就背景編譯；最後用正式尺寸暖機畫一格），蟲洞開始時若還沒好才當場做完。
- **光線**：每格在 CPU 算兩列 × 1024 的「撞擊參數 B → 掃過角度 φ」表（B<1 以 ln(1−B)、B>1 以 ln(B−1) 為座標，球邊緣也夠細；K(B) 查原本的表、F 用 16 點高斯積分），打包成 24 位元定點放進 1024×2 的 RGBA8 紋理（不用浮點紋理 → iOS 沒有浮點線性取樣也沒關係），shader 用 NEAREST 取兩點自己內插。每像素：α → B = r_c sin α → φ → 出射方向 (sinφ cosψ, sinφ sinψ, cosφ)，再算那個方向的天空。
- **天空全部 shader 程序生成**：唯一的紋理是 256×256 雜訊表。我們這邊＝深綠黑＋淡銀河帶＋暗帶；另一邊＝暖色星雲＋大螺旋星系（核球＋小亮核、2 條旋臂、沿臂的羽狀結構、團塊狀細節最多 7 層、沿臂的塵埃暗帶與細絲（會變紅）、粉紅電離氫區、旋臂上的藍星團、近看時解析出來的老年黃星顆粒）。星點：方向 → 等角立方體格點雜湊，三種尺度；每顆星用「方向對螢幕的 Jacobian」反算螢幕距離，畫成固定大小的點（σ＝`STAR_SIG` CSS px），亮星有十字光芒＋小光暈。
- **防閃爍／鋸齒**：用 dFdx/dFdy 算每像素涵蓋多大的天空 → 噪聲高頻層淡出成平均、星點層在一個點涵蓋超過半格時淡出成平均亮度、旋臂與核球先做等效模糊；壓到極限（球邊緣、光線繞很多圈）換成整片天空的平均色（GL 建好時在 GPU 上畫 96×48 全天圖算一次）。被透鏡壓縮的星依放大率 μ 變暗（`STAR_GAMMA` 讓球裡的星保留一點閃光）。抖色避免暗部色階。相鄰兩格（1/30 秒）比對：球緣與透鏡弧線沒有鋸齒或跳動。
- **解析度與自動選檔**：GL 畫布＝容器 CSS 像素 × min(dpr, 2)，長邊 ≤ 2560；品質檔 [dpr 高, 1.5 高, 1.5 中, 1.0 中, 0.75 中]。第一個 1.8 秒以時間為窗（≥ 4 格、≥ 0.35 秒）看幀時間中位數，低於 45 fps 就降一檔；之後只有 < 30 fps 才降。中品質＝少一層星點、星系細節 4 層、沒有老年星顆粒。視窗縮放／直橫轉換每格自動跟上。
