# 伽利略星球（Galileo Planet）首頁計畫 v1

2026-10-25 規劃。進度、領取與交接請看同資料夾的 `HANDOFF.md`；這份只放「要做什麼、為什麼這樣做、做到什麼算完成」。

## 1. 一句話

把首頁改成一顆可以用手拖著轉的 3D 卡通小行星「**伽利略星球**」。球上只有四座館（物理、化學、地科、生物）；學生點進其中一館，在館內可以自由逛展品，也可以用底部卡片一張一張滑過全部課程簡介（目前 139 課），想上課再按「進入」。

參考操作感：`https://keelung-planet.aipost.tw/`（真 3D、卡通描邊、手動轉動小行星）。我們只學它的「手感」與「小行星造型」，不做遊戲、人物或任務。

## 3. 資料：全部由資料檔產生，不手寫卡片

### 3.1 來源與格式

首頁現有的卡片就是資料來源。`index.html` 的結構：

- 四個科目區塊：`<div id="physics|chemistry|earth|biology" class="subject-section">`
- 區塊內每個單元：`<section class="category c-N">`，標題在 `.cat-head h2`（含 emoji，例如 `🌊 波動與聲波`），課數在 `.cat-count`
- 每一課：`<a class="card" href="xxx.html">`，內含 `.card-art img`（封面）、`.card-title`、`.card-sub`
- 英文在 `index.html` 內的 JS 字典：`INDEX_CARD_EN[href] = [標題, 簡介]`、`INDEX_CATEGORY_EN[中文單元名] = 英文單元名`
- 簡介尾端的 `★` 代表老師標記的重點課

用 `tools/museum/build_lessons.py`（或 `.cjs`，自選一種）解析，輸出 `assets/museum/data/lessons.json`：

```json
{
  "generated": "2026-10-26",
  "halls": [
    {
      "id": "physics", "zh": "物理", "en": "Physics", "sub": {"zh": "牛頓", "en": "Newton"},
      "units": [
        {
          "id": "physics-03", "emoji": "💡", "zh": "光學與透鏡", "en": "Optics & Lenses",
          "lessons": [
            { "file": "optics_2.html", "star": true,
              "zh": {"title": "平面鏡成像與反射定律", "blurb": "🪞 虛像定位、…"},
              "en": {"title": "…", "blurb": "…"},
              "cover": "assets/index_covers/menu_1008_v2/optics_2.jpg" }
          ]
        }
      ]
    }
  ]
}
```

規則：

- `lessons.json` 是**產生的檔案，不要手改**；改首頁卡片後重跑腳本。
- 沒有英文字典項目的課，英文欄位退回中文，並在腳本輸出裡警告。
- `optics_max1.html` 目前「封面待補」：腳本要有一張通用預設封面可退回。
- 學生看得到的文字不得出現「第幾單元」「第幾課」「4-1」這類章節編號（`AGENTS.md` 第八定律）。單元標籤用「emoji＋主題名」，不用數字。首頁現有的 `01 02 03` 是內部排序，不要搬進新首頁的畫面文字。

### 3.2 驗證腳本

`tools/museum/check_museum.cjs`（Playwright，沿用 `tools/qa/lib.cjs` 的 `launch()`）至少檢查：

1. `lessons.json` 的課數 ＝ `index.html` 裡 `a.card` 的數量。
2. 每個 `file` 都存在、每個 `cover` 都存在。
3. 載入 `index_museum.html` 無 JS 錯誤、無 404（favicon 除外）。
4. 四個網址 `#physics #chemistry #earth #biology` 都直接開到對應的館。
5. 館內卡片總數 ＝ 課數。

其他帳號之後新增課程時，照舊只改 `index.html`；因為 `lessons.json` 是產生的，要記得重跑腳本。**檢查腳本在課數不一致時必須失敗**，這是防止資料過期的唯一防線。

## 4. 場景與互動

### 4.1 三層結構

1. **星球**：拖曳轉動、點館。
2. **館**：鏡頭飛進，露天展場（圓形廣場，每個單元一件展品）。
3. **課程簡介**：底部卡片，按「進入」才開啟課程頁。

最多點三下進任何一課，另有搜尋。

### 4.2 星球層

- 單指或滑鼠拖曳：繞球心旋轉（arcball），有慣性；放手約 1.5 秒內緩慢回到「上方朝上」。
- 雙指縮放／滾輪：限制在近景與遠景之間（遠景看得到整顆星球與周圍雲層）。
- 四座館放在球面上正四面體頂點的方向，任何轉向都至少有兩座在可見半球。
- 館有名牌（HTML 疊在上面，不做 3D 文字）：館名、副標。點館或點名牌：鏡頭 1.2 秒飛進。
- 球本體低面數（約 5k～20k 三角形），頂點上色分陸地與海，平面著色；雲是少量低面數球體合併。
- 色彩沿用首頁色票：物理黃 `#f2d675`、化學珊瑚 `#f0955c`、地科藍 `#6fa8f2`、生物綠 `#a8e6cf`；背景天空用 `#16241f` 往亮處漸層。**不用純黑 `#000`**，描邊用 `#0b1a15`。

### 4.3 館層（進館後）

- 鏡頭停在館前廣場上方，可左右拖曳繞館一圈。
- 展品排成半圓或圓：每個單元一件。第一階段用「底座＋單元 emoji」當佔位展品，之後換成真展品（§6）。
- 點展品：底部卡片捲到該單元第一課。

### 4.4 底部導覽卡片（兩種逛法連動）

- 橫向捲動、scroll-snap。一張卡＝一課：封面圖、標題、一句簡介、★、「進入」按鈕。
- **順序**：依單元分組，單元之間在卡片列上有小分隔。
- **連動**：卡片捲到新單元 → 鏡頭飛到該單元展品；點展品 → 卡片捲過去。
- **收起**：把手可收起卡片，只剩 3D 場景；再點展開。
- **單元跳轉列**：卡片上方一排 chip（emoji＋短名），點了直接跳單元。
- **搜尋**：右上角放大鏡，展開輸入框，搜標題與簡介（中英皆可），結果以列表顯示，點結果跳到該卡。搜尋範圍只在目前這一館；兩座館之間要找就先回星球。
- 「進入」沿用目前首頁行為（`target="_blank"` 開新分頁），好處是新首頁的 3D 狀態不會因為上課而丟掉。**待老師確認**同分頁或新分頁（§8）。

### 4.5 全站固定元件

- 右上角：語言切換（中文／EN，預設繁體中文，用 `data-zh`/`data-en` 模式）、舊版清單連結、（館內才有）搜尋。
- 左上角：館內有「回星球」圖示按鈕；星球層沒有。
- 所有可點元件至少 44px。
- 字級：卡片標題 ≥ 22px，簡介與 chip ≥ 18px。主閱讀區不受 1080px 規則限制（那是教材頁的規則），但卡片文字欄寬建議 ≤ 720px。

### 4.6 路由與返回

- 網址 hash：`#planet`（預設）、`#physics` `#chemistry` `#earth` `#biology`（進該館）、`#biology/<unit-id>`（進館並定位單元）。
- 用 `history.pushState` 每層一筆：卡片 → 館 → 星球，瀏覽器上一頁逐層退。
- **相容要求**：課程頁的回總覽箭頭連到 `index.html#biology` 等；新首頁取代後，這幾個網址要一進來就直接在對應的館，不要先看到星球。
- 沒有 hash 或 hash 無效 → 星球。

### 4.7 退路

- `WebGL` 建立失敗、`webglcontextlost` 無法恢復：顯示一個友善訊息與舊版清單連結，不要空白畫面。
- 效能自動降級（§5）仍不夠時，同樣顯示舊版清單連結，但不強制轉址。
- `prefers-reduced-motion`：關掉慣性回正與環境動畫，鏡頭飛行改成短淡入。

## 5. 3D 技術規格與效能預算

### 5.1 函式庫

- Three.js 固定版本，放 `assets/museum/vendor/three.module.min.js`（連同授權檔），**不要用 CDN**（教室網路不穩）。可在暫存資料夾 `npm i three` 取檔。
- 只用核心：不用 GLTFLoader、不用後處理、不用 OrbitControls（自己寫 arcball 與飛行，比較省也好調手感）。

### 5.2 材質與外觀

- `MeshToonMaterial` ＋ 3 階 `gradientMap`（`DataTexture` 3×1）。
- 描邊：反向外殼（`BackSide`、放大約 1.03、`MeshBasicMaterial` 深綠）。
- 影子：不用陰影貼圖；腳下放半透明圓形假影子。
- 星球與展品都不用貼圖（頂點色）。例外：展窗平面（§6.3）。

### 5.3 預算（iPhone 15 Safari）

| 項目 | 上限 |
|---|---|
| 全場三角形 | ≤ 15 萬 |
| draw calls | ≤ 100（重複物件用 `InstancedMesh`／合併幾何） |
| 渲染解析度 | `min(devicePixelRatio, 2)` |
| 互動中幀率 | 星球層 ≥ 55 fps、館層 ≥ 45 fps |
| 靜止時 | 0 fps（render-on-demand；`document.hidden` 時完全暫停） |
| 首次載入 | 不含課程封面，< 3 MB |
| 館層貼圖 | 每張 ≤ 512 px；進館才載入、離館 `dispose()` |

課程封面（`.card-art`）一律用 HTML `<img loading="lazy">`，不放進 WebGL。

### 5.4 品質自動降級與除錯

- 啟動後量測前 2 秒平均每幀時間；超過 20 ms 就降低 `pixelRatio`（2 → 1.5 → 1.25）。
- `?debug=1`：顯示 FPS、每幀毫秒、draw calls、三角形數、貼圖數、目前品質檔。
- `?q=low|mid|high`：強制品質檔，方便比較。

### 5.5 iOS Safari 注意事項

- canvas 設 `touch-action: none`；整頁防止下拉重新整理與橡皮筋捲動。
- 用 `100dvh`，處理動態工具列與安全區。
- iPhone Safari 沒有網頁全螢幕：第一次進入時提示「加入主畫面」（參考基隆小行星的做法）。
- 事件監聽用 passive；處理 `webglcontextlost`／`webglcontextrestored`。

### 5.6 誠實的限制

雲端環境沒有 iPhone，且用軟體 WebGL（SwiftShader）截圖，**雲端量到的幀率沒有參考價值**。每個階段結束，都必須請老師在 iPhone 15 開 `?debug=1` 回報數字，記在 `HANDOFF.md` 的日誌。沒有真機數字，不可宣稱「效能沒問題」。

## 11. 2026-10-26 設計追加（老師討論定案）

1. **球外**：整顆球表面佔滿；39 個單元各有一個小地標（依館分區），**只看不能點**（點到就是點那一館）。
2. **進館**：鏡頭由斜視轉成正上方俯視，球體淡出，留下該館的**平面地圖**（同一個 3D 場景轉視角，不另做 2D 圖）。
3. **館內地圖**：一條彎路，單元沿路排開；路上有編號＝建議參觀順序，「下一站」標示、走過打勾（存在 localStorage，僅限本機瀏覽器，不跨裝置），也可直接點任一單元。
4. **館與館相通**：地圖邊緣有通往隔壁館的出口，點了直接飛到隔壁館的地圖。
5. **卡片版面要智慧切換（看實際寬高比，不看機型）**：
   - 直式手機：卡片在底部橫滑（現況）。
   - 寬大於高（平板 3:2 橫放、電腦）：卡片在**左側直排**、可收合，地圖在右側。
   - 近方形：底部、較矮。
   - 轉向或改變視窗大小時，版面與鏡頭要重算。
6. iPhone 15 實測：星球畫面 60 fps、12 calls、約 1.2 萬三角形（2026-10-26 老師回報），預算還很寬。
