# Physical-Boys 互動教材開發規範 v2（AI 專用）

> 本文件是給 AI／程式協作者閱讀的最高優先級開發規範。
> 目的不是重新設計老師已完成的教材，而是把既有教材優化成「老師拿到就能上課、學生一看就知道要觀察什麼」的互動教材。

---

## 0. 最高原則：原本好的，不叫待改進

優化不代表每一頁都必須改。

若原有動畫、Canvas、SVG、圖形、實驗、題目、物理模型或互動已具有良好教學功能，最佳修改就是 **不修改**。

不得因為「可以做得更漂亮」「想統一風格」「AI 可以重新畫」而重做已經調校完成的內容。

---

## 1. 最終目標：拿到就能教

最終成品不是單純漂亮的網頁，而是：

> **老師打開就知道怎麼教，學生一看就知道現在要觀察什麼。**

優先順序固定為：

**教學邏輯 ＞ 科學正確性 ＞ 原有優秀動畫 ＞ 學生注意力 ＞ 操作體驗 ＞ 視覺美化**

視覺美化不得凌駕物理正確性、教學功能或既有優秀動畫。

---

## 2. 核心教學流程

教材主要教學節奏不是：

**知識 → 解釋 → 練習**

而是：

**現象 → 疑問 → 認知衝突 → 模型 → 操作／驗證 → 概念收束**

設計每一頁時，都必須先回答：

> **學生為什麼現在需要這個模型／概念？**

Starting、動畫、問題與串場都必須服務這條教學脈絡，不可只為了熱鬧或視覺效果而存在。

---

## 3. 標題分層：導航標題與教學 Hook 絕對分開

### 3.1 外層／分頁導航標題

功能只有一個：讓老師與學生立刻知道「這一頁教什麼」。

要求：
- 簡短
- 專業
- 明確
- 接近正式教材用語
- 不塞長問句
- 不用過度花俏文案

範例：

**位置、路徑長與位移**  
*Position, Distance & Displacement*

### 3.2 點進頁面後的 Starting / Hook

學生進入該頁後，才出現吸睛問題、生活情境或認知衝突。

範例：

**「明明走了 100 公尺，為什麼位移是 0？」**

副標題可進一步引導觀察：

**「走過的路，和最後離起點多遠，是同一件事嗎？」**

Hook 必須直接服務後面的概念，不得只追求有趣。

---

## 4. 每個分頁都要有進場與退場

單元不能只是多個各自精彩但彼此斷裂的頁面。

理想流程：

**上一頁留下的問題 → 本頁 Starting → 原有內容／動畫 → 操作與觀察 → Concept Closure → 下一頁問題**

串場文字是課程的「接縫」，不是裝飾。

每次新增串場時，要確認下一頁確實是在回答前一頁留下的問題。

---

## 5. Zero Touch Policy：三區管理

### 🔴 RED ZONE｜未經老師明確指定，禁止修改

包括：
- Canvas / SVG 原有繪圖
- 原有動畫物件
- 動畫時間與節奏
- 物件座標與比例
- 運動軌跡
- x-t、v-t、a-t 圖
- 物理量關係
- 計算邏輯
- 實驗裝置與實驗呈現
- 題目內容
- 已調校完成的互動
- JavaScript 核心函式
- 已驗證的模型與動畫細節

**禁止因為想做得更漂亮而自行重畫。**

### 🟡 YELLOW ZONE｜可以提出建議，但不可自行修改

包括：
- 物理定義
- 專業術語
- 教學順序
- 公式推導
- 圖形的物理意義
- 實驗呈現方式
- 題目解法

若 AI 認為有問題：

**先指出 → 說明理由 → 等老師確認 → 才修改。**

不得用 AI 自己的物理理解覆蓋老師原有內容。

### 🟢 GREEN ZONE｜主要優化範圍

AI 可主動提出與執行的內容：
- 頁面主標題
- 副標題
- Starting / Hook
- 認知衝突設計
- 分頁標題文字
- 串場
- 教師導讀文字
- Concept Closure
- 操作提示
- 中英雙語
- iPad 排版
- Touch UI
- 資訊層級
- 留白與卡片配置
- 學生注意力引導

核心工作是：**不搶走原教材的物理設計，而是讓教材教起來更順、更容易上手。**

---

## 6. 動畫規範：動畫必須有教學功能

動畫不是裝飾。

新增或評估動畫前，先回答它是否能完成至少一項功能：
- 看見原本看不見的物理量
- 比較差異
- 建立模型
- 製造認知衝突
- 驗證學生預測
- 呈現時間變化
- 幫助學生從現象重構物理情境

已經具有明確教學功能的動畫應視為 **教材資產**，原則上不是重畫或簡化的對象。

### 新動畫提案流程

若某頁確實需要新增動畫，必須先說明：

**學生看什麼 → 操作什麼 → 預期發現什麼 → 最後形成什麼概念**

老師確認後才製作。

**新增動畫不得擅自取代舊動畫。**

---

## 7. 圖形思考高於公式套用

尤其在運動學中：

> **畫圖 = 將文字題目的物理情境重新建構。**

x-t、v-t、a-t 圖不是公式的附屬品，而是學生理解題意與建立模型的重要工具。

教學順序原則：

**讀題 → 建構情境 → 畫圖／模型 → 理解關係 → 數學表示**

不得在文案、串場或解題流程中暗示：

**「會公式之後就不需要畫圖。」**

公式應被呈現為物理／圖形關係的數學壓縮，而不是取代圖形思考的捷徑。

---

## 8. 中英雙語與預設語言防禦

### 8.1 Default Language Lock

網頁載入時預設顯示文字（`innerHTML`）必須 **100% 為繁體中文**。

英文只能存在於 `data-en` 或 Canvas 的翻譯函式中，只有使用者主動切換 EN 時才出現。

禁止中文預設介面無故夾雜英文單字；正式物理符號與必要國際符號除外。

### 8.2 固定右上角橫向語言切換

```html
<div class="floating-lang-container">
    <span class="lang-label">Language</span>
    <div class="lang-options">
        <button class="lang-pill active" id="btn-lang-zh" onclick="setLang('zh')">中文</button>
        <button class="lang-pill" id="btn-lang-en" onclick="setLang('en')">EN</button>
    </div>
</div>
```

排版鎖定：
- `position: fixed`
- `top: 20px`
- `right: 20px`
- `z-index: 9999`
- `display: flex`
- `flex-direction: row`
- 不得變成直排

視覺：深色底、青色邊框；active 為青亮色底、深色字。

### 8.3 靜態文字

標準格式：

```html
<div data-zh="中文" data-en="English">中文</div>
```

### 8.4 Canvas 動態文字

標準格式：

```javascript
tr('中文', 'English')
```

### 8.5 英文原則

一般教學文字優先使用國中生可理解的科學英文；物理、化學專有名詞則必須精準，對齊正式教科書與標準科學用語。

---

## 9. iPad Pro 13 吋為 Primary Target

設計優先順序：

1. **iPad Pro 13 吋橫式教學**
2. iPad 直式
3. Desktop
4. Phone

不是 Mobile First。

規範：
- 主內容最大寬度約 `1080px`
- Landscape 優先合理利用雙欄
- Portrait 在適當斷點改單欄
- 全域文字原則上不得小於 `20px`
- Touch target 至少 `44px × 44px`
- Canvas `width: 100%; height: auto;`
- 必要時設定 `aspect-ratio`
- 不得因 Responsive 調整改變 Canvas 內部物件座標或物理比例
- 英文切換後必須能換行，不得遮住動畫或控制項

Viewport：

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover, maximum-scale=1.0, user-scalable=no">
```

---

## 10. Touch-Friendly UI

所有：
- 播放／暫停
- 重置
- 滑桿
- 分頁
- 選項按鈕
- 語言切換

觸控熱區至少 `44px`。

操作文字使用簡潔直覺的祈使句，例如：

**調整、切換、觀察、模擬、揭曉、重置。**

---

## 11. 修改既有教材的固定 SOP

當老師說「XX 單元開始」時，**禁止直接重寫。**

固定流程：

1. 讀完整原檔。
2. 找出 RED ZONE：原有動畫、Canvas、SVG、圖形、題目、實驗與物理邏輯。
3. 分析目前教學流程與各頁功能。
4. 提出改善方案，優先限於 Starting、主副標題、串場、Concept Closure、雙語、iPad 排版與操作提示。
5. 明確列出：
   - 保留什麼
   - 增加什麼
   - 完全不碰什麼
6. 等老師確認。
7. 確認後才修改程式碼。
8. 修改後再次檢查原動畫、互動、圖形、題目是否完整存在且行為未變。

禁止流程：

**看完 → 覺得可以更漂亮 → 整份重建。**

---

## 12. 修改方式：最小侵入（Minimal Intervention）

既有教材優先採取「加法」與「局部修改」：
- 加 Hook
- 加串場
- 加雙語屬性
- 加排版保護
- 加操作提示

避免：
- 重寫整個 Canvas
- 重寫整段 JS
- 換掉原動畫
- 改動物理座標
- 為統一風格刪除既有細節

如果技術工具只能整檔覆寫，也必須以原檔為母體做最小差異修改；不能以新模板重新生成整份 HTML。

---

## 13. 完整交付規範

每次修改程式碼後必須交付完整、可直接執行的 HTML，包含必要 CSS 與 JS。

但「完整交付」不代表「整份重新設計」。完整檔必須忠實保留未被授權修改的原始內容。

修改完成後應說明：
- 修改了哪些 GREEN ZONE 項目
- 哪些 RED ZONE 完全沒有碰
- 若有 YELLOW ZONE 建議，另行提出，不自行套用

---

## 14. AI 與老師的分工

老師負責：
- 物理正確性與專業判斷
- 教學核心與課程經驗
- 原有動畫／模型的教學目的
- 最終是否修改物理內容的決策

AI 主要負責：
- 教學敘事
- Starting / Hook
- 認知衝突
- 串場
- Concept Closure
- 雙語
- UI / UX
- iPad Pro 排版
- 資訊架構
- 程式實作與維護

一句話：

> **保留老師的物理與教學靈魂，把它整理成學生願意看、老師拿起來就能教的完整互動教材。**

---

## 15. 動工前最後檢查（AI 必讀）

每次修改前，先回答：

- [ ] 我有完整讀過原檔嗎？
- [ ] 我知道哪些動畫／圖／題目是 RED ZONE 嗎？
- [ ] 這次修改是否真的有教學目的？
- [ ] 外層導航標題是否簡潔，而 Hook 放在頁面內？
- [ ] 我是否保留原本好的內容？
- [ ] 我有沒有擅自改物理定義、圖形或公式？
- [ ] 中文是否為絕對預設？
- [ ] 英文是否只存在於雙語系統？
- [ ] iPad Pro 13 吋橫式是否為主要畫面？
- [ ] 所有觸控元件是否 ≥ 44px？
- [ ] 修改後原動畫行為是否完全正常？
- [ ] 我是不是又想「順便重做」？如果是，停止。

---

# 最終鎖定句

> **先保護，再優化。先理解教學目的，再碰程式。**
>
> **原動畫是教材資產；物理內容不是 AI 的自由創作區。**
>
> **真正要優化的是 Starting、串場、注意力、雙語與上課流程。**
