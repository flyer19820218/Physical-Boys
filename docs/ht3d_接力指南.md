## 5. 血管粗細與科學正確性（老師 2026-11-22 抓到的錯，必讀）
**發生什麼事：** 小腸／肝場景的靜脈看起來「變粗又變細、外面套一層膜、像水管」。原因：**畫面上的血管粗細來自 glb 網格外殼，但血球沿中心線流，中心線半徑是另外手填的數字，兩者對不上**；上游靜脈（肝門靜脈、腸繫膜上靜脈、脾靜脈）的數字又比文獻細很多。

**已修正（2026-11-22，小腸場景）：** 這幾條靜脈不再畫網格外殼，改畫成**單層管**，粗細全部依文獻：
- 場景檔的 `SCENE.replaceMesh = { <群組>: [<中心線區段 id>…] }`：列在裡面的群組，核心會丟掉資料集網格，改依中心線與其半徑畫一根變半徑的單層管（管壁＝血流範圍）；樣式鍵（透明度、`deep.`、`glow.`）照用原群組名。
- 半徑寫在中心線 json，由 `tools/anatomy/set_vein_calibers.py` 設定（可重複執行）；`tubeRange: [u0,u1]` 可限定管畫到哪裡（例：下腔靜脈畫到右心房開口、肝靜脈畫到下腔靜脈管壁）。數字與出處在 `sources.md`「血管口徑」。
- **新場景的靜脈請照這個做**，並且口徑要有出處；動脈若網格口徑與血流一致可繼續用網格。
- 血管透明度仍要 < 0.6，血球才看得見（≥0.985 會變不透明，把管裡的血球蓋住）。
- 肝竇網、肝內分支、肝靜脈往肝內延伸：**已在肝臟場景用程式生成的示意版做出**（見 `sources.md`「肝臟場景」；不是真實解剖）。

**所以新場景一定要：**
1. 中心線半徑與畫出來的血管一致（用上面的單層管做法，或半徑直接取自網格）；程式生成的示意管，口徑要有文獻出處，記在 `sources.md`。
2. **靜脈由小到大逐段匯集、愈靠近心臟愈粗**；中間隔著微血管床時才允許變細（微血管床要畫成密集分叉網，不能只畫幾條細圈圈）。分支匯入用平順的 Y 形接點。
3. 管壁與血流是同一根管（不要網格外殼＋另一層生成管＋血球三層疊在一起）。
4. 手機（430 寬）也要看一次再交件。

**已查證的科學事實（2026-11-22，查證來源見下）：**
- 肝門靜脈把胃腸道、膽囊、胰、脾的靜脈血送進肝；這些靜脈血全部匯入它，是**單一入口**（Wikipedia〈Portal vein〉、Colorado State VIVO〈Liver anatomy〉）。
- 肝的血量約 75% 來自肝門靜脈、約 25% 來自肝動脈；肝動脈是腹腔動脈幹（源自主動脈）的分支；兩者末梢在肝竇混合 → 中央靜脈 → 肝靜脈 → 下腔靜脈（StatPearls〈Physiology, Liver〉、VIVO、LibreTexts）。
- **腎、腿、骨盆、腹壁的靜脈血不經過肝**，直接進下腔靜脈。下腔靜脈在 L5 由左右總髂靜脈匯成，沿途匯入位置（由下往上）：L1–L5 腰靜脈、L2 右生殖腺靜脈、L1 腎靜脈與右腎上腺靜脈、T8 肝靜脈與膈下靜脈，T8 穿過橫膈入右心房。腎靜脈和肝靜脈之間除右腎上腺靜脈外沒有其他分支（Radiopaedia〈IVC〉、StatPearls〈Inferior Vena Cava〉、Elsevier Complete Anatomy、Cambridge〈Atlas of Surgical Techniques in Trauma〉）。
- 小腸吸收的**脂肪**（乳糜微粒）進乳糜管 → 腸繫膜淋巴管 → 胸管 → 左鎖骨下靜脈，**不走肝門靜脈**；短鏈、中鏈脂肪酸、單醣、胺基酸才走肝門靜脈（Wikipedia〈Lacteal〉、PMC7000543、SUNY Lumen Learning Nutrition）。**教學文字不要寫成「所有養分都走肝門靜脈」。**

## 5b. 血管接點怎麼畫（方法；肺、組織細胞、肝、小腸一律照做）
老師 2026-11-22 連抓三次：接點像「三條水管插進一條套管」、管突然變細、微血管轉彎處有「球」。原因與正確做法如下，**程式範本：`tools/anatomy/build_kidney_centerlines.py`（`depart`／`arrive`／`smooth_path`／`make_branch`），出處與數字在 `sources.md`「腎臟場景」。**
1. **每段都給半徑陣列**（每個點一個值），不要用單一數字；核心場景開 `smoothTubes: true`；資料集網格的外殼若會忽粗忽細，用 `replaceMesh`（＋`replaceKind` 指定動脈／靜脈材質）改畫成單層管，網格估計值留在 JSON 的 `radius_mesh`。
2. **接點切線相接**：下游管的起點用 `depart(P, 上游切線, 弧長)`、上游匯入的末端用 `arrive(P, 下游切線, 弧長)`，先沿對方方向走一小段（幹線 10–12 mm、微血管 3–4 mm）再轉回自己的走向。分支是「順著主幹慢慢分出去」，不是垂直插入。
3. **半徑連續＋Murray 定律**：分叉處 母管半徑³＝子管半徑³ 之和；起點半徑＝上游末端半徑。匯流則由細到粗逐一匯入（每個匯入點隔數 mm，不要全擠在同一點）。
4. **管口封口規則**：同半徑、同軸相接的兩段，兩邊都 `capStart/capEnd: false`；埋進大血管壁的管口（動脈起端、靜脈末端、支流併入處）也不封；圓頭只留在游離末端。用 `tubeRange` 讓管從大血管壁外 2–3 mm 開始畫，血球仍沿完整中心線流。
5. **回頭彎（髮夾彎）**：離開與回來的方向相反時，Bezier 控制點沿兩端切線拉長到兩端距離的約 0.55 倍；檢查最小曲率半徑（點間距÷轉角）要 ≥ 管半徑的 3 倍；兩端位移用 sin² 包絡讓端點的斜率為 0。
6. **改了中心線 JSON 一定要升版號**：場景檔、頁面 JS、HTML 的 `?v=` 一起升（舊版沒帶 `?v=` 時，瀏覽器重新整理仍吃舊檔，老師會以為沒修）。
7. **驗證**：分色診斷（`HT3D._debug.viewer()` 改各群組顏色）＋近景截圖看接點；加 `V.controls.dispatchEvent({type:'start'})` 才不會被步驟鏡頭拉回去。
8. **亮度**：目標器官用 `lit.<群組>: 1`（本體色與自發光一起提亮，約 2 倍），血流亮度用 `SCENE.flowBright: 2`；不要把血管透明度調到 ≥0.6。3D 舞台高度別被舊的 `--media-h` 卡住（只有 `.expanded` 才吃）。

## 5c. 全身血管分布與粗細參考圖（老師 2026-11-23 提供；每個器官場景的血管都照這張的「感覺」做）
**圖檔：`docs/ref/vessel_whole_body_ref_20261123.png`**（全身動脈紅、靜脈藍的示意圖；來源與授權老師沒說明，**只當內部參考，不放進任何頁面、不要拿去當素材**）。老師的要求：血管要「由粗到細」，不要像「套管子」（一段一段等粗的管子互相插接）。從圖裡看得到的規則：
1. **動脈與靜脈成對並行**：主幹（主動脈、上下腔靜脈）最粗，往四肢與各器官逐級分出旁支；伴行的靜脈多半比動脈略粗。
2. **連續漸細**：離心臟愈遠愈細，沒有「突然變細」的台階，也沒有一大段等粗的水管；主幹分出旁支之後，主幹本身也略為變細。
3. **分支像從主幹慢慢分出去**：旁支從主幹側面以銳角、順著主幹方向斜出（切線相接），分出時就明顯比主幹細，不是垂直插進去。
4. **大分叉是平滑的 Y 形**：骨盆處主動脈、下腔靜脈各分成左右髂血管，是圓滑的弧線，分叉後兩條都連續往下走進腿。
5. **末梢愈分愈細**：手、腳末端分成許多細枝；進入器官（腎門、肺門）像扇形／樹枝狀逐級分叉，細枝愈分愈多。
6. **顏色只借幾何**：這張圖用動脈紅、靜脈藍；本專案 3D 不畫藍色（與 2D「兩者都是紅色」一致），只借用它的分布與粗細。

**肝臟場景怎麼落實（2026-11-23，腳本 `tools/anatomy/build_liver_centerlines.py`）**：①分叉口徑改用 Murray 定律（指數 3，先前是 2.7），每段由「本段終端數」算出起點半徑、沿路**漸細到最大子管的半徑**，同軸接續；較小的子管從母管壁分出，起點往分支那一側偏 (r大−r小)×0.85；②子管離開母管時兩端切線都對齊——用 `bez_t`（Bezier，控制點長度在 0.25–1.2 倍兩端距離間搜尋，取「最小曲率半徑最大」的）與 `join_from`，離開方向和原走向差很大（約 90°，例如肝門 T 形分叉）也不會先衝出去再折回（S 形）；③肝門的 T 形：門靜脈末 25 mm 順勢彎向最大的子支，較小的子支從末端前約 2 倍管徑處的管壁側面分出；④肝竇連接管：終端分支末段先收到連接管的起點半徑（Murray：n 條 → 終端半徑 × n^(−1/3)），連接管中段最細（肝竇）、併入肝靜脈處略粗，且順著肝靜脈血流方向併入；⑤小葉的 3 條進口、3 條小動脈、中央靜脈同樣由粗漸細；⑥封口：同軸接點不封，**終端分支的末端一律封圓頭**（肝竇連接管在步驟①②是隱藏的，不封的話樹梢會像被切斷）；⑦場景開 `smoothTubes: true`。檢查腳本：生成後跑「相對半徑變化／曲率半徑÷管半徑／管與管穿插」自訂檢查（見 PROGRESS 該行的數字）。

**5c-2　「直接變很細」的修正（同日第二次，老師：由粗到細慢慢分支、再由細到粗慢慢匯集）**：只照 Murray 畫，樹梢（門靜脈 1.25、肝靜脈 1.65 mm）和微血管（0.22 mm）差 4～7 倍，又沒有中間級，看起來就是粗管突然接細線。通則（**之後肺、組織、心肌的終端分支都照做**）：①**每條終端分支整段漸細**，不是只在最後一小段收窄：用 `leaf_profile`（接近等斜率），終端末端約為 Murray 半徑的 0.4–0.5 倍（門靜脈 0.60、肝靜脈 0.69、動脈 ×0.85）；省略掉的更細分支就當「省略」，標示意。②匯集側反過來：樹梢由細（0.69）慢慢變粗到 Murray 半徑；連接管只併入「當地半徑 ≤ 1 mm」的樹梢細端，併入處半徑＝當地管半徑 × 0.62，**不要細線撞進粗管壁**。③微血管段（連接管）由兩端的 0.4–0.5 mm 緩緩降到最細 0.22 mm 再緩緩回升；短的連接管自動墊高最細處，使每 mm 相對變化 ≤ 約 14%。④**每一級（樹梢末端→連接管最細、肝靜脈當地管→連接管）落差目標 ≤ 約 2 倍，用 `qa.py` 類的自訂檢查量，不要只用肉眼。**⑤不要為了「慢慢分支」多加流動區段：iPad（lite）血球預算 1000、每段至少 3 顆，肝臟步驟②④已用滿；要多加分支先想辦法省粒子（例如降低樹梢段密度）。

**5c-3　血管只有兩種顏色、目標血管只加亮度（老師 2026-11-23）**：①所有場景的血管材質只准兩種：`artery`（鮮紅＝充氧）與 `vein`（暗紅＝缺氧，不偏紫；2026-11-23 老師指定全站統一，色值 #5e1219／POOR #8a1a24），不要另外做「混合」「肝竇」之類的第三種材質（肝竇、肝內分支一律用 `vein`；肺動脈用 `pulmArt`、肺靜脈用 `pulmVein`＝同色對調）。②目標血管（當步講解的）靠 `glow.<群組>` 加亮，**不要用會偏色的做法**：舊的 `tint()` 會往白／粉紅偏（本體色混白、自發光固定粉紅、邊緣光 ×3.6），發亮的血管變淡粉白、和沒發亮的飽和紅管並排就像「粗管接細管」。場景寫 `vesselGlow: 'hue'` 就改成同色加亮（本體色、自發光、邊緣光都用材質自己的色相；缺氧血管加亮幅度 ×0.7）。肝臟場景已開，腎／肺／小腸還是舊做法，老師要統一時各加一行。③目標血管的 `glow` 拉到 1、其餘 0；透明度不動（< 0.6，血球才看得見）。

## 6. 驗證方法（不要重新摸索）
- 啟動伺服器：`tools/qa/serve.sh`（Port 8765；ES 模組不能用 `file://`）。
- 2D 回歸：`node tools/qa/qa_page.cjs biology_human_transport.html`，結果要與改動前逐項相同（只差動畫像素數）；另跑 `node tools/qa/smoke.cjs biology_human_transport.html`。
- 3D 截圖：Playwright chromium 要加旗標 `--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist --use-gl=angle`。沙盒是軟體算圖，**動畫時間幾乎不走**，所以一律用 `HT3D.go('<場景>', 步驟, 毫秒, {after:'stop'})` 跳到指定時間。**要「精準停在那一刻」就 `await HT3D.go(...)` 之後立刻 `HT3D.pause()`**（引擎每格最多前進 0.1 秒，軟體算圖很慢，不暫停的話等幾秒後實際時間不準）；暫停後等約 2.5 秒讓畫面更新；`getState()`／DOM 讀到的值可能落後一次切換。要看完整（非 lite）模式，Playwright 的 context 不要開 `hasTouch`（`pointer:coarse` 會自動走 lite），並用 `.click()` 取代 `.tap()`。
- 手機尺寸截圖：視窗約 430 寬、`hasTouch:true`、`deviceScaleFactor:3`，**不要開 `isMobile:true`**（它會讓 `getBoundingClientRect` 和截圖的位置差一大段）。`HT3D.go` 後 `scrollIntoView({block:'center',behavior:'instant'})`（頁面是平滑捲動，不加 instant 量到的位置會是捲動中途的），等約 1.5 秒再量舞台 canvas 的矩形；用 `page.screenshot()` 截整個視窗後自己裁切（`clip` 參數會偏）。
- 近距離看血管：`const V=HT3D._debug.viewer(); V.camera.position.set(x,y,z); V.controls.target.set(x,y,z); V.controls.update(); V.controls.dispatchEvent({type:'start'}); V.requestRender()`（dispatch `start` 讓引擎知道是使用者鏡頭，不會被步驟鏡頭拉回去）。粒子是否在管腔內：`HT3D._debug.lumen(300)`（沿管軸方向的射線打不到管壁，所以兩支血管交會處會有少數誤判，不用在意）。
- 多場景切換測試：暫時在登錄檔加一個指向同一場景檔的第二筆，跑完**一定要還原**，不能把測試項目 commit。
- 乾淨 clone 驗證：`git clone` 到暫存資料夾、另開 port 跑一次載入，看 `HT3D.getState().ready === true` 且無 404。
- 沙盒的雲端瀏覽器**沒有 WebGL**，線上實際 3D 只能請老師用電腦／iPad 看；那裡只會看到「已切回經典 2D 版」的提示（正確的退回行為）。iPad 真機效能還沒測過。
- 看圖很花額度：只看關鍵步驟的截圖。
